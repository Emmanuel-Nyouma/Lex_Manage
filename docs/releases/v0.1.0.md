# LexManage v0.1.0 — Production hardening baseline

LexManage v0.1.0 establishes the first versioned quality baseline for the multi-tenant legal practice platform.

## Highlights

- Hardened tenant isolation, authentication, authorization, validation, document lifecycle, and API error contracts.
- Added first-run onboarding, responsive loading/error states, optimistic client interactions, caching, and Android packaging through Capacitor.
- Added frontend and backend Vitest suites, including client, company settings, notification, authentication, document, case, and tenant-isolation behavior.
- Added enforceable coverage baselines and GitHub Actions jobs for lint, tests, coverage, builds, Prisma validation, dependency audits, and Docker builds.
- Split the largest company settings and notification center views into focused modules.
- Removed embedded credentials from reporting, capture, and seed utilities.
- Added Dependabot, contribution guidance, architecture notes, deployment documentation, and this changelog.
- Reconciled the Prisma schema and migration history and documented the canonical tenant identity model.
- Added a canonical Docker Compose stack for the SPA, API, PostgreSQL, Redis, and MinIO with readiness checks.

## Deployment notes

- Review every production environment variable against `.env.example` and `lexmanage-backend/.env.example` before deploying.
- Apply Prisma migrations with `npx prisma migrate deploy` as performed by the backend container.
- Capacitor is pinned to the Android Studio-compatible 7.6.8 toolchain; Android uses version code `1` and version name `0.1.0` by default.
- n8n integration remains optional, but `N8N_WEBHOOK_SECRET` is mandatory whenever an n8n webhook URL is configured.

## Verification baseline

The release is expected to pass clean dependency installation from both lockfiles, frontend and backend lint, all Vitest suites with coverage, frontend and backend production builds, Prisma validation, npm security audits, Python/Node utility syntax checks, Android Gradle assembly, and Docker Compose configuration validation.
